# Critical User Paths — device-sync

**Purpose:** Core workflows that must not break. Audit validates these end-to-end.
Status: core (incl. session, encrypted file and envelope), post (mailbox), relay (client, readers, framing, conformance), log (model, signing, exchange protocol) and trust implemented; the rest is the target.

## Library behaviour (target)

- [x] **Two devices converge** (`tests/log/exchange.test.ts`: 120 seeded schedules of three devices, each exchange signed, cut into pieces, JSON, strictly read, judged and merged, also with duplicated pieces; `tests/log/properties.test.ts` for the pure model. Pieces out of order within one session are not supported: that session ends with different fingerprints and the next one catches up) — after exchanging their changes, both hold the same data and the same fingerprint
- [x] **A forged or altered change is refused** (log layer: `tests/log/signing.test.ts`; exchange: `tests/log/exchange.test.ts`, the session ends with `forged` and the receiver's replica is unchanged) — a bad signature, a change under a foreign device id or a change outside its data set is judged false and nothing of that exchange is taken
- [x] **An envelope opens only for its readers** — a carrier sees neither sender, readers nor their number (`tests/core/envelope.test.ts`: only the listed readers open it, a stranger costs one ECDH, one derivation and at most one trial per slot; readers hidden up to a multiple of 8 slots with equal size and a shuffled, uniformly placed slot (seeded chi-square); a relabelled author, channel, content, day or app is never accepted (forged insides built with an independent `node:crypto` reference); tamper sweeps over every character; `tests/vectors-envelope.test.ts`). Honest limits: size, day, id and the carrier path are visible; a reader can re-seal and prove the author; no forward secrecy against a reader's static key; see `docs/wire-format.md`, "What the envelope hides, and what it does not"
- [x] **A new device joins by invitation** and is trusted only through the vouching strategy of the app (`tests/trust/fullstack.test.ts`: invitation text exchange, entry in the log, signed changes of the new device judged by a third replica with `readChanges` + `deviceKeySource`; a device nobody vouches for stays pending; chains, removal, forged entries; tamper sweeps and fuzzing of the three parsers in `tests/trust/meeting|invitation|fuzz.test.ts`)
- [x] **A mailbox carries envelopes within its limits and in linear time** (`tests/post/mailbox.test.ts`: every limit at its boundary, quota per device and day, expiry, receipts decided by an app predicate, hostile ids, 2000 vs 8000 entries; `tests/post/exchange.test.ts`: two devices end with the same envelopes, strict messages, enforced order, bounded per message and session)
- [x] **Two apps never share bytes** (markers, check code, change signatures, session keys and file keys per appId: `tests/core/session.test.ts`, `tests/core/file.test.ts`, `tests/core/secure.test.ts`) — different `appId`s give different signatures and keys
- [x] **A session carries messages in order and nothing else** (`tests/core/session.test.ts`: tamper sweeps, replay, duplication, reordering, dropping, reflection, counter limit; `tests/vectors-session.test.ts`) — an altered, replayed, reordered, dropped or reflected message is refused and changes no state
- [x] **A file opens only for its recipient, only from its sender** (`tests/core/file.test.ts`, `tests/vectors-session.test.ts`)
- [x] **A relay client survives errors** — it acts on the error code, never on its text (`tests/relay/client.test.ts`: every kind of failure against the reference server and scripted answers; fatal kinds are never retried, retry kinds with bounded backoff, an expired access stops further requests and re-enrols once, the access never appears in a result or a log, a hostile body is bounded; `tests/relay/readers.test.ts`: 3500 fuzz inputs per reader; `tests/relay/conformance.test.ts`: the runner passes the reference server and fails twelve broken variants)
